# AMASOLAGI integration — plan only

9 October 2026. Owner: Major Dream Williams. No AMA source changes or production deployment authorized.

## Product relationship

One shared diagnostic engine, two distinct entry experiences. MAIM serves education, clarity, and founder development. AMASOLAGI serves organizations looking for delivery support. HAMAL is the ecosystem relationship; it is not a replacement for either brand.

## Verified source context

MAIM: MajorDream444/Major-AI-OS, canonical DESIGN.md v2.3. Black foundation, crown gold, ivory, restrained legacy green and champion blue/orange; official circular MD/crown seal; a calm, open command-room aesthetic.

AMA: MajorDream444/amasolagi-site. Next.js app under src/app; existing landing page links to /contact, with separate /mobs, /how-it-works, /foundry-os and /partner-invest routes. Contact page serves clients, partners, and investors. globals.css owns the AMA dark and gold theme (#080808 / #0A0A0A, #C9A227 gold, white text, mono utility labels). Reuse its existing identity and controls rather than replacing them with MAIM gold/seal.

## Recommended first integration

Add an optional “Find your first system” / “Take the business pressure test” link beside the existing client contact pathway. Keep partnership and investor contact independent. Direct that link into the tested diagnostic service with an allowlisted entry context. Do not iframe a protected deployment or duplicate the server code inside AMA.

A later AMA-branded route /pressure-test can render a shared questionnaire package and post through an AMA-owned same-origin API adapter. Keep scoring, runtime validation, and result contracts shared; inject brand, intake copy, source, booking path, and email identity through reviewed tenant configuration. No arbitrary query parameter can select credentials or write destination.

## Proposed experience contract

| Concern | MAIM | AMASOLAGI |
| --- | --- | --- |
| Entry purpose | Understand pressure and choose a first action | Qualify a delivery challenge |
| Identity | MAIM crown seal and canonical palette | Existing AMA wordmark and metallic/dark/gold system |
| Result | Evidence, practical next move, learning/clarity conversation | Evidence, human review, suggested scope conversation |
| Intake extension | Personal work, revenue range, support readiness | Organization, role, current systems, authority, timeline, capacity |
| Follow-up | MAIM owner-reviewed next step | AMA service discovery and assigned human owner |
| Commercial behavior | No automatic purchase/credit claim | No automatic proposal, pricing, or commission commitment |

## Source and CRM requirements

Keep canonical Source choice business-pressure-test until additional source choices are explicitly added. Add entryEcosystem, campaign, diagnosticVersion and consentVersion to raw structured metadata when implemented. Match or link contacts through an owner-approved deduplication policy; never copy entire private result payloads into URL parameters.

Save the assessment first, then promote an interested, human-reviewed lead to Client Profiles / Client Clarity OS as appropriate. Do not route someone to a MOB using total score alone. Use their actual weakest signals, organization context, urgency, readiness, and agreed scope. Keep this routing internal.
